# Cell learning module: formats and renderer contract

Drop-in for the anatomy app (`/mnt/project-files/anatomy-app`, see its
`src/renderers/switch.js`, `src/renderers/xray.js`, `src/engine.js`). Every
file in `cells/` sits at the path it will have inside `anatomy-app`.
Two new renderer kinds: `"slide"` (2D stained section, pan and zoom) and
`"cell"` (3D stylised cell). Nothing here edits anatomy-app.

## Renderer contract (both kinds)

```js
// src/renderers/slide.js
export async function createSlideRenderer({ container, studiesBase = "assets/slides/", initialStudy, onPick })
// src/renderers/cell.js
export async function createCellRenderer({ container, studiesBase = "assets/cells/", initialStudy, onPick })
```

Both return the object the switch expects:

| member | behaviour |
|---|---|
| `show({ study, view, layers })` | async. Loads `study` if it is not the current one (cached), applies the named `view` from the study's `views` (unknown or missing view = the study's `defaultView`), applies `layers` (array of layer names; see per-kind lists). Returns when drawn. |
| `highlight(key, "good" \| "bad")` | tints the structure with that key green / red (same colours as xray.js: `#3fb950`, `#f85149`). Several may be highlighted. |
| `clearHighlight()` | removes all tints. |
| `name(key)` | display name from the study's `structures[key].name`, or the key itself. |
| `setDefaultLayers()` | back to the study's `defaultLayers`. |
| `setPickEnabled(bool)` | true while a question is open: a click or tap calls `onPick(key)` with the structure under the pointer and nothing else. false = explore mode: a click or tap and a hover show the name in a label; nothing is scored. |
| `setActive(bool)` | the switch hides the box when inactive; stop any animation loop when false. |
| `loadStudy(id)` | async prefetch; `show({study:id})` afterwards is instant. |
| `studyId` | getter, current study id. |
| `meta` | getter, the current study's manifest fields `{ id, title, kind, license, attribution, source, sourceUrl, stain, magnification, tissue, cells, sections, synthetic }`. |
| `debug` | getter, `{ root, state, render(), pickAt(cssX, cssY) -> key \| null, canvasOf(key) -> [cssX, cssY] of the structure's centre in container coordinates (after the current view), loading (bool), ... }` for tests. |

Keys: a structure key is a short slug (`fibre-1`, `nucleus-3`, `sarcomere`).
Keys that answer questions also carry an ontology id in `structures[key].id`
(`CL:0008002`, `GO:0005739`, `UBERON:0001134`). `target` and `accept` in a
question record are structure KEYS, not ontology ids; the check script maps
keys to ids for validation. Several structures may share a type (every fibre
is CL:0008002); `accept` lists every key that counts.

Toolbar at the TOP of the container (from 44 px down, like xray.css), so the
question panel (bottom-left, 440 px wide on desktop, full width under 600 px)
never covers it. Hover label like `.xr-label`. Loading text like `.xr-loading`.
Attach your stylesheet from the module as xray.js does. Stop the animation
loop when `setActive(false)`.

## Slide study: `assets/slides/<id>/study.json`

```json
{
  "id": "muscle-ls",
  "kind": "slide",
  "title": "Skeletal muscle, longitudinal section",
  "stain": "H&E (stylised)",
  "synthetic": true,
  "source": "Stylised illustration generated by tools/make_slides.py; placeholder until a Michigan Histology slide replaces it",
  "sourceUrl": "",
  "license": "CC BY-SA 4.0",
  "attribution": "Hand Nerves 3D project",
  "tissue": "UBERON:0001134",
  "tissueName": "skeletal muscle tissue",
  "sections": ["FMA:37664", "FMA:37670"],
  "cells": ["CL:0008002", "CL:0000594"],
  "width": 4096, "height": 4096,
  "tileSize": 512,
  "levels": [4096, 2048, 1024, 512],
  "format": "jpg",
  "micronsPerPixel": 0.25,
  "defaultView": "overview",
  "defaultLayers": ["outline"],
  "views": {
    "overview": { "cx": 0.5, "cy": 0.5, "zoom": 1 },
    "fibres-10x": { "cx": 0.42, "cy": 0.55, "zoom": 2.5, "minZoom": 2 }
  },
  "structures": {
    "fibre-1": { "name": "Skeletal muscle fibre", "id": "CL:0008002", "group": "cell",
                 "polygon": [[1200, 300], [1900, 300], [1900, 3800], [1200, 3800]] },
    "nucleus-1": { "name": "Peripheral nucleus", "id": "GO:0005634", "group": "organelle", "polygon": [[...]] },
    "endomysium": { "name": "Endomysium", "id": "UBERON:0011899", "group": "connective", "polygon": [[...]] }
  }
}
```

- `cx, cy` are fractions of the slide; `zoom` is the magnification relative to
  fit-to-view (1 = whole slide fits). `minZoom` is for Magnification questions
  (engine ignores it; the renderer exposes `debug.state.zoom`).
- Tiles: `assets/slides/<id>/tiles/<level>/<col>_<row>.jpg` where `level` is the
  pixel width of that level (4096, 2048, ...), col and row are tile indices at
  that level. Each tile is up to `tileSize` square. On a text-only host the
  renderer fetches `<same path>.b64.txt` when `CONFIG.textAssets` is true
  (read `window.__CONFIG_TEXT_ASSETS` or accept a `textAssets` option; the
  switch will pass it). A base64 text file holds the raw JPEG bytes.
- Polygons are in level-0 (full resolution) pixel coordinates, clockwise,
  non-self-intersecting. Pick = point-in-polygon, the SMALLEST containing
  polygon wins (a nucleus inside a fibre picks the nucleus).
- Layers for slides: `"outline"` (faint outline of every polygon, label
  names on hover), `"labels"` (outlines plus names drawn on the slide),
  `"none"` (no overlay; identify questions). Groups (`cell`, `organelle`,
  `connective`, `vessel`, `nerve`, `bone`) may be used by a filter row
  like xray's; optional.
- Views also take the xray string form `"cx=0.4,cy=0.3,zoom=3"`.
- A `magnification` badge: `zoom * (levels[0] / fitWidth)` is not meaningful;
  show `Math.round(4 * zoom)` + "x" and say in the README it is nominal.

## Cell study: `assets/cells/<id>/study.json`

Procedural: parts are primitives, so no glTF is needed and each cell is a few
KB. (A `model` field with a .glb URL may be added later; then `parts` only
name the meshes to pick.)

```json
{
  "id": "cl-0008002",
  "kind": "cell",
  "title": "Skeletal muscle fibre",
  "cell": { "key": "cell", "id": "CL:0008002", "name": "Skeletal muscle fibre" },
  "synthetic": true,
  "source": "Stylised model, parts placed by hand in study.json",
  "license": "CC BY-SA 4.0",
  "attribution": "Hand Nerves 3D project",
  "tissues": ["UBERON:0001134"],
  "slides": ["muscle-ls", "muscle-ts"],
  "scale": "A fibre is 10 to 100 um across and centimetres long; the model shows a short segment",
  "defaultView": "overview",
  "defaultLayers": ["membrane", "organelles"],
  "views": {
    "overview": { "eye": [0, 2.2, 5], "target": [0, 0, 0] },
    "cutaway": { "eye": [1.5, 2.5, 4], "target": [0, 0, 0], "layers": ["organelles", "cutaway"] }
  },
  "parts": [
    { "key": "sarcolemma", "name": "Sarcolemma (plasma membrane)", "id": "GO:0042383", "layer": "membrane",
      "shape": "cylinder", "pos": [0, 0, 0], "rot": [0, 0, 1.5708], "size": [1.0, 1.0, 6.0], "color": "#e8a9a0", "opacity": 0.35 },
    { "key": "myofibril-1", "name": "Myofibril", "id": "GO:0030016", "layer": "organelles",
      "shape": "cylinder", "pos": [0, 0.3, 0], "rot": [0, 0, 1.5708], "size": [0.18, 0.18, 5.8], "color": "#c9524a" },
    { "key": "nucleus-1", "name": "Peripheral nucleus", "id": "GO:0005634", "layer": "organelles",
      "shape": "ellipsoid", "pos": [1.2, 0.85, 0.2], "size": [0.5, 0.22, 0.22], "color": "#5b4a9e" },
    { "key": "sarcomere", "name": "Sarcomere (Z line to Z line)", "id": "GO:0030017", "layer": "organelles",
      "shape": "band", "pos": [0.4, 0.3, 0], "size": [0.4, 0.2, 0.2], "color": "#8b2f2a" }
  ]
}
```

- `shape`: `sphere`, `ellipsoid` (size = radii), `cylinder` (size = [rx, ry, length], axis along local Y before `rot`), `torus` (size = [radius, tube]), `box` (size = half extents), `band` (a short thick cylinder segment marking a region along a cylinder), `tube` (a smooth tube along `path: [[x,y,z], ...]`, size[0] = radius), `disc` (size = [radius, thickness]). `rot` is Euler XYZ radians. `count` + `jitter` may stamp a part several times (keys become `mito-1`, `mito-2`...; name shared); or list them explicitly.
- Units: the whole cell fits in a 6-unit box centred at the origin. Camera `eye`/`target` in those units.
- Layers for cells: `"membrane"`, `"organelles"`, `"cutaway"` (clip plane at x = 0 or hide membrane so the inside shows), `"labels"` (names drawn as sprites). Parts carry the layer they belong to; `setDefaultLayers` = study's `defaultLayers`.
- Pick = raycast on the part meshes; a transparent membrane is skipped when
  `cutaway` is on. Highlight = emissive tint, as mesh.js does.
- Controls: TrackballControls from `three/addons/` (the app's importmap maps
  `three` and `three/addons/` to `vendor/three/`). Test pages use the same
  importmap pointing at `../../anatomy-app/vendor/three/`.

## Question record (shared format, from assets/questions/ct-trunk.json)

```json
{
  "id": "hist-muscle-fibre-id", "kind": "Identify", "renderer": "slide", "study": "muscle-ls",
  "target": "fibre-2", "accept": ["fibre-1", "fibre-2", "fibre-3"],
  "prompt": "Click one skeletal muscle fibre.", "hint": "...", "view": "fibres-10x", "layers": ["none"],
  "explain": "...",
  "zoom": { "out": "model:upper-limb#FMA:37664", "in": "cell:cl-0008002" },
  "tags": { "topic": "muscle", "region": "histology", "modality": "Histology", "difficulty": 1 },
  "review": { "status": "approved", "reviewed": "2026-10-12" }
}
```

`tags.modality` is `"Histology"` for slides and `"Cell"` for cells; app.js builds the explore title from it.
`tags.region` is the tissue (`"skeletal muscle"`, `"bone"`, `"nerve"`, `"vessel"`).

## Ontology: `assets/ontology/cl-seed.json`

`{ "source": "...", "terms": { "CL:0008002": { "name": "skeletal muscle fiber", "def": "...", "parents": ["CL:0000187"], "synonyms": [...] }, ... } }`
A seed written by hand until `cl-basic.json` from purl.obolibrary.org is dropped in `raw/cl/`; `tools/import_cl.py` then regenerates the file.
